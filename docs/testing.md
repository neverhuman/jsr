# Testing and proof lanes

Every path routes to a proof command in `agent/test-map.json`; run the narrowest one
for what you touched, then `just required` before a push. Lanes are scripts under
`ops/ci/` so local runs and hosted CI execute the same commands
(`.github/workflows/jankurai.yml` calls them directly). Build settings follow
HOST_RULES: `CARGO_INCREMENTAL=0`, `CARGO_PROFILE_DEV_DEBUG=line-tables-only`
(set by the `Justfile` and `ops/ci/lib.sh`).

## Lanes

| Command | Script | What it proves |
|---|---|---|
| `just fast` | `ops/ci/fast.sh` + pytest | `cargo fmt --check`, `cargo clippy --workspace --all-targets -D warnings`, `cargo test --workspace`, and `pytest python/ultra/tests` when `.venv` exists |
| `just contract-drift` | `ops/ci/contract-drift.sh` | ledger invariants (`output_contract`) and serialised `ultra-core` events and receipts against `contracts/events/*.schema.json` (`schema_contract`) |
| `just security` | `tools/security-lane.sh` | gitleaks over the working tree, `cargo audit --deny warnings`, actionlint over workflows, shellcheck over every tracked shell script and hook |
| `just score` | jankurai audit | writes `target/jankurai/repo-score.{json,md}`; CI fails under 85 |
| `just required` / `just check` | `ops/ci/quality-gates.sh` | all of the above, in CI order; the push gate |
| `just doctor` | `scripts/ci-doctor.sh` | every tool the lanes need, found vs pinned version (`ops/ci/lib.sh`) |

Narrow commands: `cargo test -p <crate>` per crate (see `agent/test-map.json`),
`cargo test -p ultra-core --test <name>` for one contract file.

`ops/git-hooks/pre-push` runs `ops/ci/quality-gates.sh`. It is opt-in per checkout
(`git config core.hooksPath ops/git-hooks`; `ops/git-hooks/pre-commit` keeps the
jankurai diff-audit hook).

## Test families

- **Numeric contract** (`crates/ultra-core/tests/numeric_contract.rs`): requantisation
  rounding, saturation, overflow proof, N1 ranges; property tests with `proptest`.
- **Output contract** (`output_contract.rs`): the §3.1 ledger invariants and the §3.5
  lifecycle.
- **Schema contract** (`schema_contract.rs`): every event kind and both measured and
  unmeasured receipts validate against the JSON schemas; the schemas refuse unknown
  types, missing fields, extra fields and oversized payloads; the receipt schema's
  `required` list equals the Rust non-optional fields.
- **Error catalogue** (`error_catalogue.rs`): every `CoreError` variant has an entry
  in `agent/exceptions.toml` and a section in `docs/errors.md`.
- Kernel bit-exactness, front-end, eval and bench tests live with their crates; the
  spec's required correctness families are §38.1 of
  `docs/ultra/specs/ULTRA_ASR_MASTER_ENGINEERING_SPEC_v1.0-B.md`.

## Repair evidence

- A failing lane prints `FAIL lane=<name> rc=<code>`, the exact rerun command, and
  where routing and the error catalogue live (`ci_lane` in `ops/ci/lib.sh`).
- Typed refusals are `ultra_core::CoreError`. Each kind has a purpose, reason, common
  fixes, docs URL and repair hint in `agent/exceptions.toml` and `docs/errors.md`.
- Measured numbers are reported only with a receipt that
  `Receipt::validate_as_evidence` accepts; receipts for reported numbers sit under
  `docs/ultra/receipts/`. Audit reports are written to `target/jankurai/` and are
  regenerated by `just score`, never edited.
- When a jankurai finding names a path, run `jankurai diff-audit --base-ref HEAD`,
  then the mapped proof command for that path.

## Compute budget and stop conditions

Training and evaluation spend GPU and CPU time, not money through an API; JSR calls
no paid service. The limits are set by the owner rulings and the spec:

- Compute is one shared RTX 3090 (ruling O3, `docs/ultra/RULINGS.md`); running
  jobs that belong to others are never stopped to make room.
- A wave stops and is reported to the owner when a budget ceiling would be passed
  by more than 20% (spec §0.5); its verdict is `STOPPED_BUDGET`.
- Exceeding a budget ceiling is the owner's decision, never an agent's; any agent
  may stop a broken run (spec §0.4). Spend is recorded in `docs/ultra/STATUS.md`.
