# Generated and checked zones

`agent/generated-zones.toml` lists files that are written by a command or kept in
step with a source by a check. Never hand-edit a `read_only` zone; rerun its
command.

| Path | Source | Policy | Command |
|---|---|---|---|
| `contracts/events/transcript-event.v1.schema.json` | `crates/ultra-core/src/schemas/transcript-event.v1.schema.json` | `generated_output` | `cargo run -p ultra-core --bin emit-schemas --locked` |
| `contracts/events/receipt.v1.schema.json` | `crates/ultra-core/src/schemas/receipt.v1.schema.json` | `generated_output` | `cargo run -p ultra-core --bin emit-schemas --locked` |
| `Cargo.lock` | `Cargo.toml` | `lockfile` | `cargo metadata --locked` (cargo updates it) |
| `.jankurai/score-history.jsonl` | `agent/audit-policy.toml` | `auditor_output` | `just score` |

The schema documents live in `crates/ultra-core/src/schemas/`. `emit-schemas` copies
them to `contracts/events/`. Do not hand-edit the copies. JSON has no comment
syntax, so each document's `description` starts with `Generated by: cargo run -p
ultra-core --bin emit-schemas --locked` and `DO NOT EDIT BY HAND`, plus the
source path. The rest of the description is the contract text. The Rust types in
`events/` and `receipt.rs` are what the runtime enforces. The `schema_contract`
test serialises every event kind and both measured and unmeasured receipts,
validates them against the generated schemas, checks the schemas refuse bad input,
checks the receipt schema's `required` list equals the Rust non-optional fields,
and checks the generated files still match the crate source. When you change a
type, update the schema source and run `emit-schemas` in the same commit. The
test fails until they agree.

Audit reports (`target/jankurai/`) are build output, not zones; `just score`
regenerates them.
