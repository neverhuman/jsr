## Implementation and protocol

`db5c14a` adds the thin `r1-fused` bridge consumer over the existing public
`ultra-engine` API. The engine performs the frontend, encoder, greedy decoder and
detokenization with Rust AVX2/FMA kernels, packed weights and reusable working
buffers. The bridge adds no model arithmetic. The fused `load.json` records
`isa: avx2fma`, no Python runtime and no mapped ONNX Runtime/Sherpa libraries at
load. Other runtime paths remain separately identified.

Both jobs use eight streams, one inference thread, 20 ms audio packets, unpaced
complete-workload operation, controlled EOF, no tail padding, and one ready
encoder chunk per stream per engine step. Every expected instance has a checked
actual output, PCM identity and drained terminal outcome. The required-processed
watermark stays conservative until EOF drain. The bridge's terminal committed
view is not incremental Commit output or automatic speech endpointing.

The same `ultra-measure` binary places the service on CPU 52 and observer on
CPU 48, verifying separate L3/SMT domains. Governance runs on CPU 49 under the
existing lease, CPU-85% fleet guard and GPU -1. It is outside the inference
measurement tree. Guarded wall throughput, word latency, CQ, finalization delay
and FC are unavailable as performance evidence here.

The order was fixed before execution: ONNX smoke8, fused smoke8, ONNX400,
fused400. Both smoke runs passed before the complete panels. The full ONNX row
also reproduces the older D2 text and score hashes. Its CPU cost differs from the
older 0.19448 observation, illustrating why historical timings alone were an
insufficient control. Original rows are preserved.
