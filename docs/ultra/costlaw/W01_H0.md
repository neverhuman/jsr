# W01 cost law on H0 (AVX2), 2026-11-20

**Machine.** H0 = xbabe3, AMD Threadripper PRO 3995WX (Zen 2), AVX2+FMA, no AVX-512. L2 is 512 KiB per core. L3 is 16 MiB per CCX, and one core sees only its own CCX's 16 MiB. Linux 6.8.0-147, `schedutil` governor, boost not controlled. The host was shared: three Python training processes and a GPU job were running, load average about 34 of 128.

**Protocol.**
- `crates/ultra-bench` `wstream` (Appendix A ported to `ultra-kernels` AVX2), portable build: runtime feature detection, no `-march=native`.
- Rows of 1,024 weights. F ∈ {1,2,3,4,6,8,12,16}.
- Best of 3 repetitions, each of at least 0.4 s, after one untimed warm-up pass. Kernels alternate within each (size, F) point.
- One thread pinned with `taskset -c 60`. CPU 60 and its SMT sibling 124 were checked idle with `mpstat` first. No other timing run was on the host.
- Fit: `costfit`, ordinary least squares of ps per weight per pass = a + c·F.
- Checksums: all three kernels agree at every point. The 1M/64M/1536M sweep regenerates the `wstream.c` data stream, and its 24 checksums equal the Appendix A values bit for bit. The run would have aborted otherwise.
- Not done: hardware counters, the five-repetition finalist protocol, and machines A–E.

**Kernels.**
- `int8_avx2`: `vpmaddubsw` + `vpmaddwd`, 1 byte per weight.
- `t1_avx2`: T1 2-bit packing, shift-and-mask unpack to signed bytes, then the same instructions as int8.
- `tlut2_avx2`: cadence §5.3 T-LUT2 with pair-of-trits 4-bit indices, row-interleaved, 2 bits per weight. It uses `vpshufb` over a signed 9-entry table split into low and high byte planes. Cadence's 5-entry `|a0−a1|` table is not sign-exact, so it was not used.

## Reading

**Cache sizes.** One core's L3 is 16 MiB, so 1536M already streams from DRAM for a single thread. 4096M exceeds even the 256 MiB L3 of the whole chip, and its result matches 1536M within 3%.

**Comparison with §2.1** (the `[SANDBOX]` Xeon with VNNI):
- int8's fixed term is 51 ps here against 96 there. One Zen 2 core streams about 14–15 GB/s.
- The marginal term is 14–18 ps/MAC against 10.5–11. AVX2 needs two instructions per 32 MACs, where VNNI needs one per 64.
- So the split moves toward the marginal term, as host2 did in §2.2. The total stays in the same range.

**In cache.**
- T1 pays for its unpack (13.8 against int8's 3.9 at 1M), the same pattern as §2.1.
- T-LUT2 has no unpack: its fixed term is 0.2 ps in L2.
- Out of cache, T-LUT2 has the lowest fixed term and an equal marginal term. It is the AVX2 kernel to carry forward.

**T1's margin is thin.** The thread sweep below re-measured the 1-thread 1536M point on a different core set, 20 minutes later. There int8 came in at a = 41.1, so T1/int8 = 0.400, exactly at the limit. T-LUT2/int8 was 0.173. The int8 intercept moves about 20% between runs on this shared host. T-LUT2 passes with room to spare; T1 passes in one run and sits on the boundary in the other.

**Not admitted by this alone.** These are synthetic GEMV numbers. Admission needs a real layer mix, interleaved Reflex/Cortex passes and hardware counters (Appendix A, "W01 must add").

| 8 | 40.9 / 0.6 | 7.8 / 1.9 | 7.2 / 2.0 | 0.559 / 0.953 / 0.969 |

**Bandwidth ceiling.**
- The process's DRAM stream tops out at about 25 GB/s from 2 threads up: int8 F=1 reaches 23.7 GB/s at 2 threads and 25.4 GB/s at 8.
- So int8's fixed term stops falling after 2 threads, and the linear law breaks down for int8 at 8 threads (R² 0.56).
- The ternary kernels scale to 4 threads before they reach the same ceiling: 23 GB/s of packed weights, about 92 GMAC/s at F=1.
- The marginal term scales roughly as 1/threads for all kernels.
- The ceiling may be partly contention from the other jobs on the host. Hardware counters were not taken, so this is not resolved.

## Files

- `H0_wstream.csv`: raw single-thread sweep (1M/64M/1536M run plus a separate 4096M run).
- `H0_fit.csv`, `H0.json` (`ultra.costlaw/v1`): single-thread fits.
- `H0_wstream_threads.csv`, `H0_threads_fit.csv`, `H0_threads.json`: thread sweep.

**Reproduce:**

```
cargo build --release -p ultra-bench
taskset -c <idle core> wstream 0.4 --sizes 1M,64M,1536M > a.csv
taskset -c <idle core> wstream 0.4 --sizes 4096M > b.csv
costfit <combined.csv> --json H0.json
```
