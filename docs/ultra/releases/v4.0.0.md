# Isosyll v4.0.0 (2026-11-25): one Rust binary, three platforms

**Status:** Published 2026-11-26T00:45:09Z as the Latest release, after all three qualification gates passed.

## What it is
- **A packaging release.** One user-facing binary, `isosyll`, replaces the two research decoders and their long flag lists. It is pure Rust and loads the INT8 safetensors model, with no Python, PyTorch or ONNX runtime.
- **The model is unchanged.** The weights are the v3.1.0 RC2 INT8 bundle, byte for byte (`weights.int8.safetensors` sha256 `94a9879f…`). The language models are the v3.1.0 files: `lm/live.ulm` is `c4_p0_0_10_40.v2.ulm` (`113c4562…`) and `lm/final.ulm` is `M5.ulm` (`72a621c2…`).
- **The decoder settings are the released ones,** built in as defaults:
  - **Final:** commit chunk 16, beam 16, M5 LM at scale 0.80 with LODR 0.60, 320 ms tail pad, one thread.
  - **Live:** 160 ms chunk, beam 4, live LM weight 0.70 with LODR 0.50.
  - The headline accuracy, speed and energy in the README and the paper are therefore the v3.1.0 measurements, and the parity and timing checks below tie them to this binary.
- **Platforms:**
  - **Linux x86-64:** a glibc build (glibc 2.35 or newer; links only libc, libm and libgcc_s), which is the timed build. A fully static musl build ships as the fallback for Alpine and older systems.
  - **Linux arm64:** a static musl build.
  - **macOS on Apple silicon.**
  - `install.sh` picks the right file.
- **Gate status:** v3.1.0's registered gate misses still apply (5,540 against 5,489 full-DEV final edits; 800 against 722 live-with-LM panel edits; 722 against 650 final panel edits). v4.0.0 changes no model or decoder behaviour, so it closes none of them.

**Release:** <https://github.com/neverhuman/jsr/releases/tag/v4.0.0>. Tag `v4.0.0`, tag object `c636e779907412d7df903d15e2f92f4c8dcb128e`, tag commit `c562b3427d8358e5bddc6fbb93eb8b6cd6f8e570` (the build commit).

## Install and run
```bash
curl -fsSL https://github.com/neverhuman/jsr/releases/latest/download/install.sh | sh
isosyll transcribe meeting.wav
```
The installer verifies the signature and every checksum before it installs anything. Without `ssh-keygen`, it stops unless you pass `--checksums-only`. It puts the binary in `~/.local/bin` and the model in `~/.local/share/isosyll/model`. The README has the manual steps.

| Command | What it does |
|---|---|
| `isosyll transcribe AUDIO...` | Final text (commit pass). Audio up to 40 s is one commit pass, identical to `ultra-engine-commit`; longer audio is cut at the quietest point 20–30 s into each piece. |
| `isosyll transcribe --mode live AUDIO...` | 160 ms live text, identical to `ultra-cold-wav` with the live LM. No length limit. |
| `isosyll stream AUDIO` | Replays a file at real time. Live partials go to the terminal and committed segments to stdout. |
| `isosyll model verify` | Checks every model file's sha256 against `MANIFEST`. |

## Qualification
Receipts are in `releases/v4.0.0-qual/` on the data drive (sealed `SHA256SUMS`). The references are the signed v3.2.0 decoders: `ultra-engine-commit` for final text and `ultra-cold-wav` with the live LM for live text. All three gates were registered before the runs.

| Gate | Build | Result |
|---|---|---|
| 1. Transcript parity, 730 panel utterances | x86-64 glibc, x86-64 musl, macOS Apple silicon (NEON) | 730/730 final and 730/730 live, byte-identical, on each |
| 1b. Release-binary parity, 50 clips | all four release binaries (arm64 Linux under emulation) | 50/50 final and 50/50 live on each (400/400) |
| 2. Relative CPU vs v3.2.0, 6 paired blocks on one pinned core, upper 1-sided 95% bound ≤ +2.0% | x86-64 glibc | final: median +0.13%, upper +1.94%, **pass**; live: median −0.46%, upper +1.17%, **pass** |
| 2 (fallback) | x86-64 static musl | live: upper +1.90%, pass; final: median +2.57%, upper +3.51%, **miss** |
| 3. Clean install from the signed files | `ubuntu:22.04`; `alpine:3.20` with `ssh-keygen`; bare `alpine:3.20` with `--checksums-only` | glibc picked on Ubuntu, musl on Alpine; signature and checksums verified; `isosyll model verify` passed; 5/5 final and live transcripts matched |

- **Why x86-64 ships glibc first:** the static musl build missed the final-mode CPU gate, an allocator effect in the beam-16 commit pass. It ships only as the untimed fallback for systems without glibc 2.35.
- **Tested binary vs released binary:** the timed glibc binary (built from d9377da) and the released one (built from c562b34) differ only in the 20-byte GNU build ID and the 12-character build-commit string. The Rust source between the two commits is identical.
- **After publishing:** the one-line install from the public URL was re-checked in a fresh `ubuntu:22.04` container (signature, `model verify`, and a transcript matching the reference).

## Build provenance
- `ops/release/build.sh` builds stripped binaries with `--locked` on the pinned Rust toolchain (1.95.0). The paths of the build host are remapped out of them.
- **Linux x86-64 (glibc):** built by `ops/release/build-glibc.sh` inside `ubuntu:22.04`. It fails if the binary needs anything newer than GLIBC_2.35.
- **Static musl builds:** linked with `rust-lld`, with no C cross-compiler.
- **macOS:** built on an Apple silicon host from the same commit.
- **Build commit:** every binary prints it (`isosyll --version` → `isosyll 4.0.0 (c562b3427d83)`).
- `ops/release/model.sh` builds the model archive from the signed v3.2.0 bundle and LMs.
- The archives are deterministic: entries in sorted order, uid/gid 0, mtime 0, and `gzip -n`.
