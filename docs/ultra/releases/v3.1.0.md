# ULTRA v3.1.0 (2026-11-24): the RC2 model, signed, with its files

**Status: published** 2026-11-24T23:54:58Z, marked Latest.

**What it is:**
- The RC2 INT8 model (REGctl boundary, step 43,980, EMA), the two measured decoder binaries, the two LM packs and the pinned scorer.
- Both decoders (`ultra-engine-commit`, `ultra-cold-wav`) were built from source commit `3bd85e9eab41371e4ca17c02c007a104f9e6fc4a` ("3bd85e9e", the R6 build); `ultra-score` is the v3.0.1 file. These are the exact bytes that R6's quiet-host timing ran (see "Kit provenance"). The confirmatory look decoded the live modes with `ultra-engine-eval` from the same build, which is not shipped.
- The qualification, every number and the limits are in the [RC2 record](v3.1.0-rc2.md).

**Gate status, stated plainly:**
- RC2 missed the registered full-DEV M5 final gate by 51 edits (5,540 against 5,489), the 160 ms live-with-LM policy recorded 800 panel edits against its 722 target, and the M5 final recorded 722 panel edits against its 650 target (see the RC2 record).
- The owner approved releasing RC2 as v3.1.0 on 2026-11-24 (about 22:50Z, direct instruction to the lead in session) regardless.

**WER receipts against timing receipts:**
- The confirmatory look decoded the three live modes with `ultra-engine-eval` (feature-shard input, glibc >= 2.39, not shipped). R6 timed the same policies with `ultra-cold-wav` on WAV files. The policy values (chunk, beam, LM, weights) are identical.
- **Full-panel parity:** codex verified that all 730 R6 `ultra-cold-wav` transcripts equal the confirmatory `ultra-engine-eval` hypotheses exactly, in all three blocks and for all live arms (AGENT_CHAT.md 2026-11-24T23:39:32Z and 23:43:01Z, codex-paper-audit). I also compared them (9 arm-block files against the three live score inputs, plus the three `final_m5` block outputs against the final score input): 0 byte mismatches out of 730 in each. The R6 outputs name utterances `uNNNNN`; I mapped them to LibriSpeech ids as the panel's dev-clean utterances in score-input order, then its dev-other ones. That order is inferred, but it agrees with the transcripts on all 730.
- **Final mode:** same flags as the look. R6 passes `--max-sym-per-frame 1` explicitly and the look's script omits it; the default at 3bd85e9e is 1 (`crates/ultra-engine/src/bin/engine_commit_eval/cli.rs:59`), so the two agree.
- `--threads 1` applies to the final pass (`ultra-engine-commit`) only; `OMP_NUM_THREADS=1` applies to every mode.

## Install
Same flow as [docs/release.md](../../release.md#install-the-pinned-release), with the v3.1.0 file names; the model directory is `int8/` and needs no FP32 weights. Example (final text, from the install directory; `commit.jsonl` rows hold `uid`, `provisional`, `committed` and timings, then one summary row without `uid`; the live decoder `ultra-cold-wav` instead writes `{"id", "hyp"}` rows for WAVs named `u00000.wav`, ...):
```bash
./ultra-engine-commit --model int8 --manifest utts.jsonl --out commit.jsonl \
  --commit-chunk 16 --commit-beam 16 --max-sym-per-frame 1 --commit-lm M5.ulm \
  --lm-scale 0.80 --lodr-scale 0.60 --token-bonus 0.0 --tail-pad-ms 320 --threads 1
```
