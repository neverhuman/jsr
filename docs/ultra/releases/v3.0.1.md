# ULTRA v3.0.1 (2026-11-23): the v3.0.0 artifact, signed, with its files

**What it is:**
- The v3.0.0 artifact, re-issued as a **signed release with its files attached**.
  - The artifact is the RC1 EMA INT8 weights, the release decoder, the M5 LM and the scorer.
  - It uses the same commit as v3.0.0 (`9c8c05e5a07daaf783bb46f9878fa96aa1ac4f9b`).
- **Nothing changed in the code, the weights or the decoder.**
- The qualification, every number and the limits are in the [v3.0.0 record](v3.0.0.md).

**Why a new tag:**
- v3.0.0's tag was cut with a placeholder git identity and is unsigned. Its GitHub release first had no files.
- The owner chose a new signed tag on the same commit over re-cutting v3.0.0, so v3.0.0's tag stays as it is.
- v3.0.0's release later got the same files (same bytes), unsigned.

**Release:** <https://github.com/neverhuman/jsr/releases/tag/v3.0.1> (Latest, published 2026-11-23T20:03:05Z).

## Checks before publishing (claude-lead, 2026-11-23)
- **Sources:** each source file matched the qualified kit list (eval-lane's `KIT.SHA256SUMS` for RC1's release decoder) before packaging, and every copy was hashed again.
- **The tar:**
  - it is deterministic: sorted names, fixed mtime, numeric owner 0;
  - it round-trips: unpacking it reproduces every bundle file's hash.
- **Reproduction:** the release files reproduce the qualified release-row text **byte for byte** on a spot check.
  - The check covered the first 4 dev-clean utterances, both live (`provisional`) and final (`committed`) text, against eval-lane's `raw.jsonl`.
  - One process with one thread had a peak RSS of 702 MB.
- **Signatures:**
  - every signature verifies with `allowed_signers`, and a tampered copy fails;
  - `git verify-tag v3.0.1` reports a good signature.
- **Upload:**
  - the release was created as a draft;
  - every asset's size on GitHub matched the local file;
  - `SHA256SUMS`, its signature and the decoder were downloaded fresh and verified;
  - only then was the release published.
- **Independent check:** Codex verified the v3.0.1 SSH signature separately (AGENT_CHAT.md, 20:04:31Z).
