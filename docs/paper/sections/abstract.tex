\begin{abstract}
On one four-core Zen~2 core complex, the \ultra multirate streaming transducer sustains
\DenMRCore{} live streams per physical core (\DenMRCCX{} per complex) with worst-worker p99
lateness under 800\,ms, against \DenRzeroCore{} per core for a pretrained Zipformer INT8 in the same
harness: \DenRatioMR{}$\times$ the passing load (bracket \DenRatioMRBracketLo--\DenRatioMRBracketHi{}
given the rung spacing), identical in all \DenReproRuns{} rehearsal runs. At an equal load of 32
streams it uses \CostRatioMR{}$\times$ less CPU per audio second (\CostLadderMR{} vs.\
\CostLadderRzero), and in eight counterbalanced single-stream blocks its median CPU time is
\AbabMedianMR{}$\times$ Zipformer's. Accuracy lags, and training continues: \WerRehearsalMR\% against
\WerRehearsalRzero\% WER on the same 400 dev-clean panel utterances. The engine behind this is
pure Rust and integer-exact: per-row centred INT8 makes each stream's output independent of its
batch, within \GateMaxDelta\pp WER of FP32, and with a portable log-mel front end the tokens decoded from raw
PCM are bit-identical on x86 AVX2 and ARM NEON (\XisaAgree/\XisaTotal{} decodes). A multirate
encoder runs ten of sixteen blocks at \MidRateHz\,Hz; a dense finalist sustains \DenDenseCore{}
streams per core at \WerRehearsalDense\%. All results are exploratory (20\,s ladder rungs, shared
host) under a pre-registered protocol whose qualifying run is pending.
\end{abstract}
