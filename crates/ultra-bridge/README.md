# Measured CPU research bridge (M1)

`ultra-bridge` runs the delivered `train.bundle_infer.BundleRecognizer` and the
native R0 Zipformer control on the same audio, with Rust pacing, collection,
integrity checks, whole-service accounting and Rust scoring. It admits **DEV only**.
This temporary Python inference path is authorized by the owner-supplied benchmark
plan and the lead's M1 handoff in `AGENT_CHAT.md` (2026-11-20 19:23 UTC).

The worker imports NumPy/ONNX Runtime and the bundle consumer. It receives binary
PCM, opaque instance IDs, offsets and permitted inference configuration. It has no
dataset, references, reference times or scoring inputs. Rust prepares audio outside
the timed service and opens references only after that service exits. Neither
export nor quantization runs inside inference.

## Reproduce a DEV run

Run from the active repository root. Outputs below are generated by these source
commands and stay outside Git. Use the core partition and lease in `AGENT_CHAT.md`.

```sh
cargo build --release -p ultra-bridge -p ultra-eval --bins
/mnt/xbabe3-external/jsr/cargo-target/main/release/ultra-bridge prepare \
  /mnt/xbabe3-external/jsr/cache/librispeech_pcm/dev-clean.npz \
  /mnt/xbabe3-external/jsr/runs/bridge/m1-dev-audio dev-clean 400
```

For R0 change `engine` to `r0-native`, `bundle` to the verified
`r0-zipformer-int8` bundle and `out` to a fresh directory. Keep the identical
`inputs`, streams, threads, packet size, pacing and core. R0 uses the existing
native sherpa batching API; its observations are timestamped by this driver.
It adds the existing 800 ms EOF tail padding. R1 uses its declared EOF rule.

For native R1 use `engine: r1-native` with the same R1 bundle and a fresh output
directory. Start with FP32. It calls `OrtTransducerBackend` in the measured Rust
service, batches compatible encoder chunks and emits the same checked observations
and output artifacts. Native jobs can omit `python` and `worker`; their unused
source-hash fields contain SHA-256 of empty bytes. `load.json` binds the actual
ORT library, precision and bundle and records `python_runtime_used: false`.
The same full-service scope includes cold load, validation, features, decoding,
output collection and drain. It preserves the conservative EOF-only processing
watermark and experimental receipts. Native implementation parity, INT8 quality,
latency and deployment qualification are independent gates.
Native services enforce `timeout_s` with a scoped deadline thread. Expiry ends
the isolated service with status 124, and the outside observer records an invalid
run. Its CPU and thread cost are included in the service measurement.

The guard wrapper applies the recorded fleet policy to the actual driver and
worker process groups. It retains guard source, effective job and governance logs
outside the measured service tree. Guarded wall throughput and model-batch wall
timings are unavailable as performance evidence, even when the observed duty is
1.0. CPU consumption and sampled memory remain exploratory shared-host readings.

`paced: true` releases each packet only after its final sample's capture deadline.
This is a complete-workload run, with no duration cutoff or completed-subset score.
The highest capacity, automatic endpointing and sustained-operation claims require
the common benchmark suite and its later qualifying window.

The result directory is newly created; existing directories are refused. A failed
worker, timeout, wrong sequence/identity, missing/extra/duplicate result, wrong PCM
digest, incomplete drain or measurement failure produces `invalid.json` and no
valid receipt. A successful empty transcript requires an explicit drained outcome.

`plan.json` binds the workload, bundle manifest, source commit/dirty state, actual
driver executable, worker and consumer hashes, effective settings and host snapshot.
`events.jsonl` records real monotonic observations with normative ledger events.
`observations.jsonl` retains conservative processing evidence; `outcomes.jsonl`
accounts for every expected instance. `receipt.json` retains unavailable counters
as null. `summary.json` separates measurement integrity (`valid`) from evidence
completeness (`evidence_valid`, `evidence_gaps`). Unknown decoder cap counters
(R0/Nemotron), guarded timing and uncommitted runtime source prevent qualification.
Every bridge receipt has `completion_status: exploratory`; this CLI cannot issue
a profile-qualified receipt even from clean source on an unguarded host. Timed
event hashes establish exact-log integrity and naturally vary with timestamps and
interleaving. A/A checks compare source-sorted final/commit transcript views.
R0/R1 expose terminal committed text at Final; neither emits incremental Commit
events here. Nemotron's unavailable preview/commit views are empty files.
`checksums.json` binds the inference artifacts. Scoring checks those hashes before
writing `scores.jsonl`, `score.json`, `score.md`, `support.json` and their hashes.

The scoring library is the same authority as `ultra-score`. Independently rescore
or compare the saved records, preserving the speaker clusters and recommended
10,000 bootstrap replicates:

```sh
/mnt/xbabe3-external/jsr/cargo-target/main/release/ultra-score \
  R0/scores.jsonl R1/scores.jsonl --replicates 10000 --seed 20261120
```

## Scope of measurements

Optional `service_cpus` and `observer_cpus` job fields apply to R0, R1 and the
Nemotron control. Supply both, for example `"service_cpus": "52"` and
`"observer_cpus": "48"` on the recorded H0 topology. The measurement binary also
accepts `--service-cpus LIST --observer-cpus LIST`. It refuses offline CPUs,
unknown topology and any CPU/SMT/L3 overlap before starting inference. Choose
available cores under the current host lease; example IDs are not a reservation.
Pin the outer launcher and fleet guard away from the service CPUs as well. For
this H0 example, a permitted launcher core 49 shares the observer's L3 domain
and leaves the service's domain separate; pass the same guarded command through
`taskset -c 49` instead of inheriting core 52. These job fields move the measurer
and service, not the surrounding governance processes.

The observer pins its own thread, sets and checks the service mask in the child
before exec, and records both effective masks. Child threads and processes
inherit the service mask. Later service/thread affinity drift is not monitored;
the report states this limitation. The observer mask is checked at bind and
after drain. No placement claim is made when these optional fields are absent.
`measurement.observer_cpu_seconds` records observer setup-through-drain CPU,
excluding result serialization; this is outside inference service CPU. The
configured polling interval and sampled peak process count are also recorded;
individual process-tree scans can overrun that interval and miss brief peaks.
Old measurement JSON
loads these previously unavailable fields as null. Existing retained rows and
their source/runtime identities are unchanged by this instrumentation update.

CPU and aggregate sampled RSS/PSS/threads cover the entire inference service tree,
including cold load, audio I/O, IPC, feature extraction, decode, output formatting,
collection and orphan drain. The measurement observer, reference preparation and
offline scoring are outside that tree for both arms. `load.json` records cold load
separately. R0/R1 warm CPU is total CPU minus a process-tree snapshot immediately
after load; the snapshot's clock-tick resolution is explicit. Model-batch timings
exclude IPC and no-op packets; their batch occupancy scope is explicit. RSS is the observer's conservative
sum of process high-water marks; PSS and thread peaks are sampled every 20 ms.

The consumer has no authoritative streaming per-sample processing watermark.
The bridge credits required processing only after completed EOF drain. Its backlog
series is explicitly an **upper bound**, unsuitable for backlog qualification.
CQ, FC, stable-word latency, automatic endpointing, capacity qualification
and deployment qualification remain unavailable. The run manifest and report
state these limits; unit-test success never supplies missing measurements.

Training cost and original training-source provenance come from trainer records,
not this service. Dynamic INT8 uses the exported encoder/joiner while the decoder
and remaining floating-point operations stay FP32. Same-precision parity and INT8
quality are separate questions.

## Nemotron completed-file control

`run-nemotron JOB.json` uses the same audio manifest, Rust whole-service observer,
outcome validation and `score RUN CACHE` command. Its separate job fields are
`inputs`, `candidate`, `candidate_id`, `binary`, `model`, `out`, `concurrency`,
`threads`, `chunk_ms`, `measure`, `timeout_s`, `host_window` and `guarded`.
Use `run_guarded.py BINARY JOB.json --nemotron` under the same lease and affinity.
The candidate YAML and actual CLI/model/shared-library hashes are retained.
The service creates fresh WAVs from verified PCM and requires one actual UTF-8
output file per expected input. Missing output is an error; explicit empty output
is valid. Positive loaded CPU-backend evidence is required.

The complete CLI tree, WAV formatting, load, decode and collection are measured.
The CLI does not expose a separate warm CPU snapshot, decoder caps, internal model
batch counts or live event timestamps. These fields remain unavailable. Its
560 ms operating point is a completed-file quality/cost control here and carries
`unknown-overlap`; it receives no streaming latency claim from this wrapper.

## Verified export preparation

`run_guarded.py .venv/bin/python EXPORT_JOB.json --export` calls the delivered
`train.export.export_bundle` API outside inference. It verifies trainer source
against the immutable starting commit, checks unchanged source after export,
verifies payloads and writes `source-provenance.json`. Existing directories are
refused. This verifies export source and checkpoint identity; it does not
reconstruct provenance missing from the original training launch. ONNX, NumPy,
Torch and ONNX Runtime versions are captured. Inference imports no Torch.
